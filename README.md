# Юрий Пак · GraphQL-визитка

Бэкенд-визитка на Node.js, TypeScript, NestJS, Apollo Server, Prisma и PostgreSQL. Через GraphQL доступны профиль, профессиональные ссылки, навыки, опыт работы и проекты.

## Запуск через Docker Compose

Понадобятся Docker Engine и Docker Compose v2. Из корня репозитория выполните:

```bash
docker compose up --build -d
docker compose logs -f api
```

Когда в логах появится `Nest application successfully started`, откройте [Apollo Sandbox](http://localhost:3000/graphql) и нажмите **Run**. Запрос `DeveloperCard` уже есть в редакторе при первом открытии. Корневой URL перенаправляет на `/graphql`. При занятом порте задайте `CARD_PORT` в окружении или в `.env` и откройте соответствующий порт.

```graphql
query DeveloperCard {
  profile {
    name
    description
    links { label url }
    skills { name }
    experience {
      company
      position
      startedAt
      endedAt
      achievements
    }
    projects { name url description }
  }
}
```

PostgreSQL получает отдельный Docker-том. `docker compose down` останавливает приложение и сохраняет данные. Для проверки с отдельной чистой базой можно запустить новый Compose-проект, например `docker compose -p card-fresh up --build -d` после остановки основного.

## Архитектура

- `src/profile/profile.resolver.ts` связывает GraphQL-поля с методами сервиса. Типы GraphQL объявлены отдельно от моделей Prisma, поэтому наружу выходят только поля визитки. Схема генерируется из TypeScript при старте. Apollo Sandbox и интроспекция включены для просмотра публичного API.
- `src/profile/profile.service.ts` обслуживает один публичный профиль и переводит даты опыта в `YYYY-MM`. Поля, которые пользователь выбрал, запускают свои `@ResolveField`. Сервис запоминает промис каждой загрузки на время одного запроса, поэтому повторное обращение к полю через алиас или фрагмент использует ту же загрузку.
- `src/profile/profile.repository.ts` отвечает за фильтрацию, выборку и сортировку через Prisma. `profile { name }` вызывает одну выборку. Полная визитка вызывает до пяти выборок: профиль и по одной на каждую из четырёх связей. Выборка связи загружает весь её список сразу, поэтому число SQL-запросов не растёт с числом навыков, мест работы или проектов.
- `prisma/schema.prisma` хранит профиль, ссылки, навыки, места работы и проекты в связанных таблицах. Внешние ключи защищают целостность данных, индексы поддерживают выборку по профилю и заданный порядок. Достижения хранятся в массиве PostgreSQL внутри записи об опыте: они читаются целиком вместе с ней. Опыт выдаётся от поздних дат начала к ранним, `endedAt: null` обозначает текущую работу.

## Миграции и данные

Compose дожидается готовности PostgreSQL. Затем при каждом старте контейнер выполняет `prisma migrate deploy`, синхронизирует профиль и запускает HTTP-сервер. `GET /health` возвращает `200`, когда приложение может выполнить запрос к PostgreSQL, и `503`, если база недоступна.

[prisma/profile-data.ts](prisma/profile-data.ts) содержит данные визитки. Чтобы обновить их, измените файл и пересоберите приложение. Seed держит всё обновление в одной транзакции. Сначала `upsert` создаёт профиль или блокирует его строку для записи, затем seed заменяет связанные списки. При ошибке изменения откатываются. Повторный запуск синхронизирует записи с файлом без дублей, в том числе удаляет исключённые из файла элементы. Идентификаторы связанных записей остаются внутри БД.

## Запуск напрямую через Node.js

Подготовьте пустую базу PostgreSQL и файл `.env` по образцу `.env.example`. Укажите `DATABASE_URL` для пользователя с правом применять миграции. Используйте Node.js 22 (от 22.15) или 24.

```bash
npm ci
npm run build
npm start
```

Пока API работает, выполните `npm run smoke` во втором терминале. Проверка обращается к HTML-странице Apollo Sandbox, `/health` и GraphQL API, проверяет заполнение всех разделов, сортировку опыта и выборку с алиасами. Для другого адреса задайте `BASE_URL` в окружении.

## Развёртывание на Render

Загрузите репозиторий на GitHub. В панели Render выберите **New → Blueprint**, подключите репозиторий и примените [render.yaml](render.yaml). Blueprint создаст веб-сервис из `Dockerfile` и привяжет к нему PostgreSQL через `DATABASE_URL`. После успешной проверки `/health` откройте `/graphql` на выданном Render HTTPS-адресе. Для сдачи задания отправьте этот адрес и ссылку на репозиторий. Бесплатная база Render действует 30 дней, а бесплатный веб-сервис может запускаться с задержкой после простоя. [Документация Render](https://render.com/docs/free)
